### 2. 添加止盈止损计算检查清单 (engine.go:465-480行)
**新增内容**:
```
## 止盈止损计算检查清单（生成决策前必须验证）

**做多验证**:
1. `take_profit > stop_loss` (止盈价高于止损价)
2. 假设入场价 `entry = (stop_loss + take_profit) / 2`
3. 风险空间 `risk = entry - stop_loss`
4. 收益空间 `reward = take_profit - entry`
5. 验证 `reward / risk >= 3.0` (风险回报比≥1:3)

**做空验证**:
1. `stop_loss > take_profit` (止损价高于止盈价)
2. 假设入场价 `entry = (stop_loss + take_profit) / 2`
3. 风险空间 `risk = stop_loss - entry`
4. 收益空间 `reward = entry - take_profit`
5. 验证 `reward / risk >= 3.0` (风险回报比≥1:3)

**示例**:
- ✓ 做空: SL=0.178, TP=0.166, entry=0.172 → risk=0.006(3.5%), reward=0.012(7.0%), 比例1:2
- ✗ 做空: SL=0.18, TP=0.17, entry=0.175 → risk=0.005(2.9%), reward=0.005(2.9%), 比例1:1 (不满足1:3)
```

**改进效果**: AI有了详细的计算步骤,可以在生成JSON前自我验证

## 发现的不一致性

### 问题: Prompt要求1:3,但代码验证1:2
**System Prompt** (engine.go:255行):
```
1. **风险回报比**: 必须 ≥ 1:3（冒1%风险，赚3%+收益）
```

**验证代码** (engine.go:773,789行):
```go
if rewardDistance < riskDistance*2.0 {  // 验证的是2:1,不是3:1!
```

### 建议修正方案

**选项A**: 将验证标准统一为2:1
- 修改System Prompt: "必须 ≥ 1:2"
- 保持代码不变: `riskDistance*2.0`

**选项B**: 将验证标准统一为3:1
- 保持System Prompt: "必须 ≥ 1:3"
- 修改代码: `riskDistance*3.0`

**推荐**: 选项A (2:1更实用)
- 原因: 3:1的要求过于严格,会错过很多合理的交易机会
- 2:1是业界常见的保守标准
- 当前失败的DOGEUSDT案例(1:1)仍然会被正确拒绝
